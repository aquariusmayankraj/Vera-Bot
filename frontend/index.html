TWO SERVICES. ONE WORKING APP.

From local to live.

You control deployment. This interface never deploys on your behalf.

01

Backend → Render

Create a Python Web Service from your repository. Use the settings below for the full ZIP structure.

Root directory
backend
Build command
pip install -r requirements.txt
Start command
python start.py
Health check
/v1/healthz

Copy the public HTTPS base URL once your service is live.

02

Frontend → Netlify

Set the Render URL in frontend/config.js. Upload only the frontend folder to Netlify Drop.

API_BASE_URL: "https://your-service.onrender.com"

No npm install, framework build, or API key is needed for this static frontend.

03

Connect & verify

Open your Netlify site, check connection, and start a demo conversation. In Render, set CORS_ORIGINS to your Netlify origin.

Set optional FRONTEND_URL in Render to add your website link to the backend landing page.

04

Submit the right URL

Share the Netlify URL to show the interface. Submit the Render base URL to the challenge judge.

Never append /v1 to the submission URL. Required endpoints remain at the Render root.

Storage & cold starts: Render Free may sleep and lose local SQLite data on restarts, redeploys, or spin-down. For retained state, use a paid service with a persistent disk and DB_PATH on that disk. See the included deployment instructions for the exact setup and official sources.

This is a challenge message engine, not a general-purpose LLM or a live WhatsApp integration. It returns drafts and actions; it does not send real messages, publish listings, confirm bookings, or make payments.
